# Decisions

| Topic | Decision | Why |
|---|---|---|
| Name | Ease | An animation principle, like Squash, Stretch and Arc |
| Physics bindings | jolt-jni | Better maintained than writing and keeping our own |
| ECS | Fleks | Kotlin-first and maintained; the engine adds phases and replication on top |
| Editor viewport | Engine and Stretch share one wgpu device; Stretch reads each frame back for Compose | No public way to hand a wgpu texture to Compose on the GPU; the readback holds 60 fps (see `editor/viewport-and-play.md`) |
| Windows and gamepads | SDL3 through LWJGL 3.4 | One native library for windows, their native handles (the Metal layer on macOS) and gamepads with rumble, gyro and a broad controller database |
| Lighting path | Clustered forward+ first; deferred optional behind the same pipeline interface | Custom shading and transparency favor forward+; materials never know the path |
| Networking | Network-ready from day one; single-player runs as a local host plus a local client over loopback | Authority and replication bugs surface immediately instead of being patched in later |
| P2P signaling | Deferred; client-server and direct connect first | The object model matters at the start, the matchmaking path does not |
| In-game UI | Own engine UI, drawn by the renderer | Controller-first focus navigation and one look across HUD, menus and dialogue |
| Target hardware | A Steam Deck class floor machine at 60 fps and 1280×800, with the budgets in `targets.md` | One concrete low-end machine turns performance into numbers every feature is held to |
| Hot-path math | Immutable `ease-math` types for the API, plus in-place forms (`…Into(dst)`, operations on `float[]`) for hot paths | Allocation budgets then hold by construction instead of depending on the JIT removing temporary objects |
| Command serialization | kotlinx.serialization: JSON for agents, scripts and plugins; a compact binary form for the command log and the network; schemas for `describe` written at build time | One declaration serves every reader of a command; replicated components keep their own KSP serializers for quantized deltas |
| Agent tools | The official MCP Kotlin SDK over streamable HTTP on 127.0.0.1, in a host-layer module | The same stack Arc runs; both libraries pass the license rule |
| Versioning | Semantic `0.x` releases, exact pins in game projects, an integer `formatVersion` with step-by-step code migrations on every surface outside the repo (see `versioning.md`) | Game repos upgrade on purpose, and old files and saves keep loading without golden fixtures |
| Phase 2b modules | New ranks: `ease-serialization` between core and world; `ease-assets`, `ease-scene` and `ease-net` between platform and GPU, in that order. Network ids, authority and the replication annotation live in `ease-ecs`; `Transport` and the loopback transport in `ease-net` | Commands must name network ids and prefab GUIDs, so both sit below the world layer; assets need the platform's file watcher, and asset reloads apply as commands |
| Asset identity | A sidecar `.meta` file per source file holds its GUID, a random UUID v4; sub-assets take a UUID v5 from the parent's GUID and their name. A moved file keeps its GUID because its meta file moves with it; a meta file left without its source is matched to a new file by content hash | Binary sources cannot carry a header; v5 keeps sub-asset ids stable across reimports |
| Scene and prefab files | YAML, one file per scene or prefab, written by a canonical writer (sorted keys, shortest round-trip floats, conservative quoting, no timestamps, identical bytes when nothing changed) and read with snakeyaml-engine into the kotlinx.serialization tree; a `formatVersion` key and code migrations as in `versioning.md` | YAML block lists have no separators, so two people appending nodes do not touch each other's lines; one file per scene keeps scenes readable, and sublevels split large levels |
| Nodes | A node is an entity at runtime with a `NodeKey` (placement path plus a random 64-bit local id) and a `Parent` component; the child holds its parent and an order key, never the parent a child list; slots are `NodeRef` and `AssetRef<T>`; overrides are a path of local ids, component type and field, plus a value | Random ids never collide across branches; links on the child mean adding a child touches only the new node; placement paths keep two copies of one sublevel apart |
| Merging content | Merge conflicts are allowed but must be resolvable by hand: editor-only state (camera, selection, expanded rows) goes in a git-ignored per-user file; binary assets use Git LFS locking; an asset check in CI fails on a meta file without a source, a source without a meta file, a duplicate GUID or an unresolved reference | Opening a scene never changes it, and a bad merge is reported by name instead of loading wrong |
| Replicated serializers | KSP 2.x (decoupled from the Kotlin version) generates quantized delta serializers from annotated Kotlin components; schema-driven serializers cover components described at runtime. Components keep `@Serializable` for full-precision files | Walking kotlinx descriptors per field at runtime allocates and is close to reflection |
| File watching | The JDK `WatchService` behind a `FileWatcher` interface in `ease-platform`; changes apply at the next tick boundary; tests use a fake watcher | Native events on Windows and Linux, no new dependency; macOS polls, which is enough for hot reload during development |
| Network simulator | Latency, jitter, loss, duplication and bandwidth caps counted in ticks on a manual clock, with a seeded schedule | Prediction tests stay deterministic and never wait |
